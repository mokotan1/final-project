# Story 50 Round Match Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the story mode's stage/300-point end condition with one 50-pair match and verify every rule in the approved design.

**Architecture:** Keep the existing story-specific GML dispatch and physics. Introduce one round-progress state owned by `scr_story_versus`, one saturating story-score path, and a single post-shot transition. Adapt existing HUD/dialogue/AI hooks without changing endless/classic rules.

**Tech Stack:** GameMaker GML, Windows PowerShell capture tools, Python source checks, Igor VM build.

**Spec:** `docs/design/2026-10-22-story-50-round-match.md`

## Global Constraints

- Before any gameplay code edit, capture actual current story mode screen/video in `docs/devlog/2026-10-22-story-50-round/before/` and identify whether the build matches current source.
- Preserve all existing dirty and untracked files. Do not clean or restore the checkout.
- `STORY_MAX_TURNS=50`, `STORY_SCORE_MAX=999999999`; break is 0 pairs, player then bartender completes each pair.
- No stage target, chance depletion, or score lead may end the match before pair 50.
- Story-specific changes only; endless/classic behavior must remain intact.
- Implement using Cursor `composer-2.5` via `run-cursor-subagent.ps1` if a Cursor worker is used; the Codex lead independently reviews the result.

## Review Focus

- Break scoring must not increment the pair count.
- AI pass, zero score, and foul must not stall or double-increment the count.
- A large risk-shot cushion count must saturate before exponentiation; both total scores must stay within bounds.
- Dialogue/banner/purchase input gates must not allow an early shot or skip a result.
- An old stage checkpoint must not leak into a new match.
