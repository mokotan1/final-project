# 스토리 모드 50합 단판 설계안

작성일: 2026-10-22  
상태: 구현 전 설계안. 사용자는 기존 기획서의 추천안 적용과 점수 상한 설계를 승인했다. 위험 샷 파울의 누적 점수 초기화는 기존 동작 유지로 설계하며, 실제 밸런스는 플레이 검증에서 확인한다.

## 1. 목표와 범위

스토리 모드를 스테이지별 목표 점수 경기에서 손님과 바텐더가 **50합을 주고받는 한 판**으로 바꾼다. 50합이 끝난 뒤 누적 점수를 비교해 승리·패배·무승부를 정한다. 경기 중 어느 쪽이 300점 또는 다른 점수에 먼저 도달해도 종료하지 않는다.

이 설계는 스토리 모드의 진행·종료 규칙을 다룬다. 공의 이동·충돌, 샷 점수 확정, 아이템 효과, 공통 시각 효과는 가능한 한 현재 구현을 사용한다. 엔드리스·클래식 모드의 규칙은 변경 대상이 아니다.

## 2. 현재 구현과 변경 지점

| 영역 | 현재 코드 | 설계안 |
| --- | --- | --- |
| 진행 단위 | `story_stage_index` 0~15와 스테이지별 목표 점수 | 브레이크 0합, 이후 손님 샷과 바텐더 샷을 한 쌍으로 하는 1~50합 |
| 종료 | 스테이지 목표 달성 또는 기회 소진 | 50번째 바텐더 차례가 확정된 뒤 점수 비교 |
| 브레이크 | 스토리 진입 시 바텐더 브레이크 샷 | 유지. 점수는 반영하되 합에는 넣지 않음 |
| 점수 | 양쪽 누적 점수와 별도 `stage_points` | 양쪽 누적 점수만 승패 판정에 사용 |
| 기회 | 양쪽 3개, 무득점 시 감소·득점 시 회복 | 50합 경기에서 제거 |
| 스테이지 규칙 | 최소 쿠션·파울 세금·회복 제한·위험 샷 계약 | 적용하지 않음 |
| 저장 | 이전 스테이지와 체크포인트 점수를 로드·저장 | 한 판을 매번 새로 시작, 완료 결과만 저장 |

첫 스테이지 목표는 현재 300점이다. 한 번의 샷으로 300점 이상을 얻을 수 있으므로 현재 게임이 한 차례씩 친 직후 끝나는 현상은 이 종료 조건과 양립한다. 실제 실행 빌드의 메뉴 전환 경로는 별도로 재현해 확인한다.

## 3. 규칙과 불변식

1. `completed_pairs`는 **완료된 손님·바텐더 샷 쌍의 수**이며 시작값은 0, 최댓값은 50이다. 화면의 현재 합은 브레이크 중 0, 이후 `completed_pairs + 1`이다.
2. 브레이크 샷은 바텐더만 실행한다. 브레이크 점수는 바텐더 누적 점수에 반영하지만 `completed_pairs`를 증가시키지 않는다. 브레이크가 끝나면 손님의 1합 차례로 간다.
3. 각 합에서 손님 차례가 먼저, 바텐더 차례가 나중이다. 득점·0점·파울 모두 차례 하나를 완료한 것으로 센다. AI가 샷 후보를 찾지 못하면 기존 패스 경로를 이용하되 해당 차례를 완료한 것으로 센다.
4. 손님 샷 확정 직후에는 바텐더 차례로 간다. 바텐더 샷 또는 패스 확정 직후 `completed_pairs`를 정확히 한 번 증가시킨다.
5. `completed_pairs < 50`이면 다음 손님 차례를 시작한다. `completed_pairs == 50`이면 결과를 확정하고 추가 샷과 상점 구매를 막는다. 합 카운트는 결과가 확정된 뒤 다시 증가하지 않는다.
6. 승패는 아이템 구매 비용과 확정된 파울 효과까지 반영한 **최종 누적 점수**로 결정한다. 점수가 같으면 무승부로 처리한다.
7. 경기 종료 전에는 점수 우위·300점 도달·스테이지 목표·기회 소진으로 종료하지 않는다.

### 상태 흐름

`규칙 안내 → 브레이크(0합) → 1합 손님 → 1합 바텐더 → … → 50합 손님 → 50합 바텐더 → 결과 → 메뉴`

기존의 대사 타이머·턴 배너·AI 지연은 유지할 수 있다. 다만 실행 허용 여부는 현재 단계와 차례에서 한 곳에서 판단해, 대사 중 타격·상점 구매 또는 결과 뒤 AI 샷이 발생하지 않게 한다. 상태 표현을 새 `story_phase` 하나로 통합할지는 구현 전에 기존 이벤트와 타이머의 의존 관계를 확인한다. 이 리팩터링 자체가 50합 규칙의 필수 조건은 아니다.

## 4. 종료 판정 인터페이스

스토리 전용 `story_versus_check_match_over()`가 **완료된 합 수만** 경기 종료 트리거로 사용한다. `story_versus_on_shot_ended()`는 점수·파울을 확정한 뒤, 브레이크인지 일반 합의 어느 차례인지 구분하여 차례/합을 진행하고 종료 판정을 호출한다. AI 패스도 동일한 차례 완료 경로를 통과한다.

`story_winner`는 손님·바텐더·무승부를 구분한다. 결과 데이터에는 양쪽 최종 점수, 차이, 완료 합 수와 결과 대사 ID를 남긴다. 술값은 승리 전액 할인·무승부 반값·패배 할인 없음으로 **문구만** 표시한다. 실제 금액은 표시하지 않는다.

### 점수 상한과 위험 샷 계산

스토리 점수 전용 상수 `STORY_SCORE_MAX = 999999999`를 둔다. 손님과 바텐더의 누적 점수는 항상 정수 `0..STORY_SCORE_MAX` 범위에 있어야 한다. 이 상한은 게임 점수의 안전 범위이며, 모든 고득점 샷을 이 값까지 허용하겠다는 밸런스 목표는 아니다.

- 일반 샷은 기존 `100 × 2^쿠션 수`, 위험 샷은 기획서의 `100 × 10^쿠션 수`를 사용한다. 위험 샷 0쿠션은 100점이다. 현재 코드의 `2쿠션 이상 = 10,000점` 고정 처리는 이 설계에 맞게 변경한다.
- `power()`로 큰 값을 먼저 만든 다음 `min()`을 적용하지 않는다. 위험 샷은 6쿠션까지 계산하고 **7쿠션 이상은 즉시 `STORY_SCORE_MAX`**를 반환한다(`100 × 10^7`이 상한을 넘음). 일반 샷도 곱하기 전에 남은 상한과 비교하여 포화 계산한다. 음수·비정상 쿠션 값은 득점 계산 경계에서 0 이상 정수로 정규화한다.
- 점수 추가는 스토리 전용 함수 하나로 모은다. 현재 점수와 확정 샷 점수를 각각 `0..STORY_SCORE_MAX`로 정규화하고, `shot_points >= STORY_SCORE_MAX - current_score`이면 상한을 반환한다. 그렇지 않을 때만 둘을 더한다. 두 팀에 같은 함수를 사용한다.
- 아이템 비용은 기존처럼 손님 점수에서 차감하되 결과를 0 이상으로 제한한다. 위험 샷 파울이 손님 누적 점수를 0으로 만드는 **기존 특수 벌칙은 유지**한다. 이때도 점수 범위 불변식을 만족시킨다.
- HUD 점수, 점수 차, 결과 화면은 상한까지 표시할 수 있도록 실제 렌더링을 확인한다. 상한에 도달한 뒤의 추가 득점은 점수를 더 올리지 않는다. 양쪽 모두 상한이면 동점으로 판정한다.

의사코드(실제 GML 함수와 변수명은 구현 시 정리):

```text
STORY_SCORE_MAX = 999999999
story_score_add(current, points):
    current = clamp_to_integer(current, 0, STORY_SCORE_MAX)
    points = clamp_to_integer(points, 0, STORY_SCORE_MAX)
    if points >= STORY_SCORE_MAX - current: return STORY_SCORE_MAX
    return current + points

story_risk_points(cushions):
    cushions = max(0, floor(cushions))
    if cushions >= 7: return STORY_SCORE_MAX
    return 100 * 10^cushions
```

상한은 **점수 산출**과 **누적 점수 기록** 양쪽에 적용한다. 한쪽만 막으면 큰 중간값이나 다른 직접 대입 경로가 남는다. 현재 코드에서 점수 대입 경로는 `story_versus_add_score_to_active_side`, `story_versus_on_target_hit`, 아이템 구매, 위험 샷 파울, 이전 체크포인트 로드, 스테이지 파울 세금이다. 새 단판에서는 체크포인트 로드와 스테이지 세금을 제거하되 나머지는 전부 점검한다. `global.score`처럼 공통 점수를 변경하지 않고 스토리의 `story_player_score`·`story_ai_score`에만 적용한다.

결과 화면에서 Enter 또는 클릭하면 메뉴로 이동한다. 결과가 표시되자마자 자동으로 메뉴로 이동시키지 않는다. 사용자가 보고한 즉시 메뉴 이동은 현재 빌드의 입력/룸 전환 경로를 작업 전 촬영에서 확인한다.

## 5. 화면·대사·AI

- HUD의 스테이지명, 스테이지 목표, 기회 표시를 현재 합 `N/50`, 양쪽 누적 점수, 점수 차, 현재 차례로 바꾼다. 브레이크 중에는 `브레이크`로 표시한다.
- 배너는 `N합 · 손님/바텐더 차례`를 표시한다. 50합은 마지막 합임을 명시한다. 25·40·50합 대사는 각 합의 손님 차례 시작 때 한 번만 표시한다.
- 시작 규칙 안내, 샷 반응, 결과 대사의 우선순위를 정한다. 결과 대사가 최우선이며, 대사·배너가 활성인 동안 샷과 구매를 잠근다. 문서의 `RULE-*`, `TURN-*`, `RESULT-*` ID를 연결하되 대사 원문은 원본 데이터와 대조한다.
- 바텐더 AI는 1~10합 약하게, 11~39합 현재 수준, 40~50합 전력으로 선택하도록 설계한다. 손님이 1,500점 이상 앞서면 약하게 치는 구간을 조기 종료한다. 약하게 친 샷에 대한 `GENTLE` 대사는 경기당 최대 2번 사용한다. 실제 후보 순위·조준 오차·위험 가중치는 고정 배치 시뮬레이션과 플레이 기록으로 조정한다. 브레이크 샷은 이 난이도 곡선과 별도로 유지한다.
- 상점은 손님 차례, 공 정지, 대사·배너 종료 후에만 연다. 현재 가격과 점수 차감 방식을 우선 유지한다.

## 6. 저장 및 이전 기록

`story_stage_index`와 체크포인트 점수는 새 경기에 읽거나 쓰지 않는다. 예전 INI에 이 키가 있어도 새 판은 0합·양쪽 0점에서 시작한다. 결과 완료 시 기존 `story_first_match_done`을 기록한다. 중간 저장은 하지 않는다. 승리 횟수와 최고 점수 차는 이번 구현에 추가하지 않는다. 나중에 중간 저장이 필요해지면 합 번호뿐 아니라 양쪽 점수, 다음 차례, 공 위치와 관련 효과/아이템 상태까지 저장해야 한다.

## 8. 검증 및 개발 일지

코드 수정 전에 실제 1280×720 스토리 경기의 시작, 첫 손님·바텐더 차례, 기존 종료 화면을 스크린샷과 짧은 영상으로 `docs/devlog/<날짜>-story-50-round/before/`에 기록한다. 실행 불가 시 오류와 촬영하지 못한 항목을 기록하고 촬영 자료로 표시하지 않는다. 수정 후 같은 모드·해상도·가능한 한 같은 입력으로 `after/`를 남긴다.

필수 검증 사례:

1. 브레이크가 바텐더 점수에는 반영되고 완료 합 수는 0이다.
2. 손님 샷만 끝나면 합은 아직 완료되지 않으며, 바텐더 샷·패스 후 정확히 1 증가한다.
3. 300점을 넘어도 끝나지 않는다. 49합 뒤에는 계속하고 50합 바텐더 차례 뒤에만 결과가 난다.
4. 50합 종료에서 손님 승·바텐더 승·동점 세 경우가 정확히 표시된다.
5. 무득점·파울·AI 패스가 있어도 합이 멈추거나 두 번 증가하지 않는다.
6. 이전 스테이지 저장값이 있어도 새 경기가 0합·0점으로 시작한다.
7. 확정한 위험 샷 점수식·파울 벌칙·아이템 효과가 적용되고 엔드리스·클래식 동작은 유지된다.
8. 한글 폰트 검사, 프로젝트 정적 검사, GameMaker VM 컴파일과 실제 Runner 화면 검증을 수행한다.
9. 위험 샷 점수는 0/1/2/6/7쿠션에서 각각 100/1,000/10,000/100,000,000/`STORY_SCORE_MAX`이고, 일반 샷도 큰 쿠션 수에서 상한을 넘지 않는다.
10. 손님·바텐더 모두 `STORY_SCORE_MAX - 1`에서 1점 추가 시 상한에 도달하고, 그 뒤 추가 득점에도 범위를 벗어나지 않는다. 아이템 차감·위험 샷 파울 후에도 점수는 0 이상이다.
11. 두 팀 모두 상한이면 동점이며, 9자리 점수와 점수 차가 1280×720 HUD·결과 패널에서 잘리지 않는다.

50합 전체 실플레이 외에 테스트 설정에서 최대 합을 5로 줄여 경계와 세 결과를 빠르게 검증한다. 이 설정은 배포 빌드의 50합 값을 바꾸지 않아야 한다.

## 9. 확정한 선택과 확인할 위험

기획서 추천안에 따라 동점은 무승부·술값 반값, 기회 제거, 스테이지 특수 규칙 중단, 10합까지 약하게 치되 손님이 1,500점 앞서면 조기 전환, `GENTLE` 대사 최대 2회, 중간 저장 없음, 술값은 문구만 표시, 브레이크는 0합으로 확정한다.

위험 샷은 기획서의 `100 × 10^쿠션`에 점수 상한을 적용한다. 위험 샷 파울 시 누적 점수 0 초기화는 기존 동작을 유지한다. 두 팀이 모두 상한에 도달하면 이후 득점으로 우열을 가릴 수 없으므로 무승부가 된다. 이 경우가 실제 플레이에서 자주 나타나면 점수식 또는 샷별 상한을 별도 밸런스 결정으로 조정해야 한다.
