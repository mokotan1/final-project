# AI 5쿠션 상한 해제와 접전 샷 선택 (2026-10-28)

## 의도와 작업 전

- 사용자는 손님과 바텐더가 실제 샷으로 비슷한 실력을 보이길 원한다. 예를 들어 손님 10,000점, 바텐더 5,000점이면 바텐더가 5~6쿠션 경로를 찾아 점수 차를 약 2,000점 이내로 줄이거나 역전할 수 있어야 한다. 점수를 직접 보정하거나 득점을 보장하지 않는다.
- `before/story-initial.png`, `before/story-final.png`, `before/story-flow.mp4`: 수정 전 정식 빌드를 스토리 50합·1280×720 화면에서 300프레임 촬영하고 180프레임째 플레이어 샷 입력을 보냈다.
- `before/runtime_stdout.txt`: 같은 점수와 공 배치에서 실제 GML 시뮬레이터에 6쿠션 이상 득점 경로가 있지만 AI 선택 검사가 `ai-six-cushion-catchup`으로 실패했다. 기존 AI는 5쿠션 초과 후보를 버렸다.

## 변경

- AI의 유효 후보에서 5쿠션 상한을 제거했다. 시뮬레이션 길이 720 Step과 점수 상한은 유지한다.
- 50합 경기에서는 예상 샷 후 점수 차가 약 ±2,000점에 가까워지는 경로를 우선한다. 바텐더가 2,000점 이상 뒤질 때는 주변 각도 5개 중 2개가 유효해도 후보로 고려해 고쿠션 추격 경로를 선택할 여지를 늘렸다. 앞서 있을 때는 불필요한 고득점을 피한다.
- 첫 10합의 soft 샷은 손님 리드가 2,000점 미만일 때만 유지한다. 이후에는 일반 후보 탐색으로 전환한다.
- 손님 리드 100,000점 이상에서 바텐더가 위험 샷을 구매하면 실제 위험 샷 점수 공식으로 후보를 다시 평가한다. 일반 점수로 고른 고쿠션 샷에 위험 배율을 붙여 점수 차가 폭증하는 문제를 막는다.
- ±2,000점 기준과 느슨한 주변 각도 기준은 50합 경기에만 적용한다. 다른 스토리 대결의 후보 평가는 기존 방식으로 둔다.

## 작업 후와 검증

- `after-final/story-initial.png`, `after-final/story-final.png`, `after-final/story-flow.mp4`: 최종 빌드를 같은 게임 모드·화면 크기·300프레임·플레이어 입력으로 촬영했다. 브레이크 난수 때문에 공 배치는 다르다. `after/`는 위험 샷 재평가 보완 전 중간 촬영본이다.
- `after/runtime_stdout.txt`: 6쿠션 이상 추격 후보, 바텐더 선두 시 낮은 점수 후보, 위험 샷 점수 재평가, 기존 50합 결과 케이스가 PASS. 실제 공을 친 뒤의 물리 결과를 보장하는 검사는 아니다.
- `python tools/test_story_versus.py`, `python tools/validate_project.py`, Igor VM 빌드가 통과했다. 최종 실행 파일은 `Build/CushionChallenge-2026-10-28-ai-competitive.win`, 로그는 `compile.log`다.
- 하네스의 한 배치에서 후보 탐색 한 번에 약 874ms가 걸렸다. 이는 동기식 AI 탐색 시간의 단일 측정값이며 장시간 평균이 아니다. 실제 경기에서 AI 턴의 멈춤과 난이도 체감은 추가 플레이로 확인해야 한다.
