# 바텐더 위험 샷 실패 기회 (2026-10-28)

## 의도

손님에게 점수를 더하거나 바텐더 점수를 주기적으로 차감하는 원안 대신, 바텐더가 손님보다 100,000점 이상 앞설 때 경기당 한 번 무작위 턴에 위험 샷을 실패하게 한다. 실패한 위험 샷은 기존 위험 샷의 누적 점수 소실 규칙에 따라 바텐더 점수를 0으로 만든다. 적격 바텐더 턴마다 25% 확률로 선택하며, 50합까지 격차가 유지되면 마지막 턴에 선택한다.

## 작업 전 기록

- `before/`에는 코드 수정 전 `Build/final_project.win`의 스크린샷과 240프레임 영상이 있다. 확인 결과 이 빌드는 50합 경기가 아닌 검증 장면이었다. 같은 장면의 직접 전후 비교 자료로 사용하지 않는다.
- `before-production/`에는 이전 `Build/CushionChallenge-2026-10-27.win`을 같은 절차로 촬영했으나, 이 빌드도 50합 이전 장면이었다.
- `before/story-50-reference/`는 2026-10-27 `story-balance-ai-items/after/`의 50합 경기 자료를 출처를 밝히고 복사한 참고 자료다. 이번 세션의 수정 직전 촬영으로 간주하지 않는다.

## 변경과 수정 후 기록

- `scripts/scr_story_ai/scr_story_ai.gml`: 바텐더 리드 100,000점 이상에서 위험 샷 실패 기회를 경기당 한 번 예약한다. 선택된 샷은 목표 공에서 멀어지는 방향으로 친다.
- `scripts/scr_story_versus/scr_story_versus.gml`: 예약된 위험 샷의 정산 때 바텐더 누적 점수를 0으로 만들고 점수 소실 효과와 비차단 반응 대사를 표시한다. 발동 합과 전후 점수를 Runner 로그에 남긴다.
- 손님 아이템 가격 200/800/400, 바텐더 아이템 가격 800/3200/1600으로 분리했다. soft 종료 9,600점, 적극 아이템 3,200점, 접전 대사 1,600점 기준을 적용했다.
- `after/`의 첫 촬영은 자동 입력이 도입 화면을 넘기지 못해 비교 자료로 사용하지 않는다. `after-retry/`는 수정 후 정식 빌드의 50합 경기 화면과 240프레임 영상을 같은 1280×720 화면·입력으로 촬영했다. 10만 점 리드 상황을 주입하지 않았으므로 실패 이벤트 자체는 영상에 나타나지 않는다.

## 빌드와 남은 검증

- GameMaker Igor VM 빌드가 성공해 `Build/CushionChallenge-2026-10-28.win`을 생성했다. 컴파일 로그는 `compile.log`이다.
- 사용자가 직접 플레이 검증을 맡기로 했다. 특히 10만 점 경계, 실제 샷 연출, 경기당 1회 제한, 샷 뒤 점수 0 처리의 체감을 확인해야 한다.
