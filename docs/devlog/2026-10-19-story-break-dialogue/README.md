# 스토리 대사와 AI 브레이크 샷

## 작업 전

- `before/user-story-before.png`는 사용자가 제공한 실제 스토리 화면이다. 대화·결과 패널이 테이블 중앙을 크게 가린다. 이번 작업에서 직접 촬영한 영상은 아니다.
- 코드 변경 전 `tools/capture_story_ai.ps1`로 기존 `Build/final_project.win`을 실행하려 했으나 Windows `{잘못된 DLL 재할당}` 오류로 Runner 창이 열리지 않았다. 따라서 이번 작업에서 직접 촬영한 화면·영상은 없다.

## 작업 후

- 스토리 각 스테이지는 바텐더 차례로 시작하며, 테이블 중앙에 목표 공과 파울 공 두 개를 삼각형으로 모아 놓는다. 바텐더 공은 오른쪽에서 가운데 목표 공을 향해 강한 브레이크 샷을 친다. 검증 모드의 기존 공 배치는 유지한다.
- 시작 대사나 샷 반응 대사가 보이는 동안 AI 타격 지연을 시작하지 않는다. 대사 타이머가 모두 끝난 뒤 1초를 기다리고 브레이크 샷 또는 일반 AI 샷을 실행한다.
- 일반 대화창을 테이블 상단 가장자리의 낮은 띠로, 경기 결과와 스테이지 클리어 패널을 테이블 아래쪽으로 옮겼다.
- `tools/test_story_versus.py`, `tools/validate_project.py`, `tools/story_ai_fixture_sim.py`와 GameMaker Igor VM 컴파일을 통과했다.
- 제한된 실행 환경에서는 Windows `{잘못된 DLL 재할당}` 오류가 났고, 일반 데스크톱 권한 실행 요청은 자동 승인 검토의 모델 용량 오류로 실행되지 않았다. 사용자가 일반 데스크톱에서 Runner를 직접 실행하고 `tools/capture_existing_runner.ps1`을 실행해 실제 게임 프레임 197개를 촬영했다. 스크립트가 목표 240프레임 전에 종료되어, 연속 프레임을 `after/story-break-partial.mp4`(19.7초)로 묶었다. `after/initial.png`는 메뉴, `after/final.png`는 샷 후 공이 흩어진 스토리 화면이다. 영상에서 대사 중 중앙 3공 배치와 대사 종료 뒤 공이 흩어지는 상태를 확인했다. 목표 프레임 수에 못 미친 원인은 확인하지 못했다.
