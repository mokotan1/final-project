# 바텐더 아이템 우선순위 실제 Runner 확인 (2026-10-29)

## 목적과 방법

2026-10-27 아이템 우선순위 수정의 미완료 플레이 확인을 이어서 수행했다. `tools/run_bartender_item_playcheck.ps1`로 검증 전용 빌드를 만들고 GameMaker Runner에서 실제 공 이동과 턴 정산까지 실행했다. 검증용 소스 주입은 빌드 직후 원래 파일로 복원했다. 세 상황은 같은 스토리 50합 모드, 1280×720 게임 설정, 16합 시작 상태를 사용한다. 테스트 빌드는 세 상황을 순서대로 진행하고 각 AI 턴 종료 시 아이템 횟수, 점수, 파울공 수, 복원 대기 배열, 위험 샷 예약 상태와 턴 번호를 `runner_stdout.txt`에 기록한다.

샷 선택 입력을 고정하기 위해 검증 빌드에서 `story_ai_pick_shot()`의 반환값만 주입했다. 아이템 구매, 실제 타격과 물리 이동, 샷 종료 및 턴 전환은 게임 코드를 그대로 실행했다. 따라서 이 결과는 고정한 후보에 대한 아이템 우선순위와 턴 종료 상태를 확인하며, AI가 임의 배치에서 그 후보를 스스로 찾는다는 증거는 아니다. 별도 화면 녹화는 수행하지 않았으며 아래 자료는 Runner 로그다.

## 결과

| 상황 | 고정 조건 | 턴 종료 결과 |
|---|---|---|
| 안전한 득점 후보 | 예상 1,600점, 동쪽 방향, 파울공은 경로 밖 | 아이템 `이동 0 / 위험 0 / 제거 0`, AI 2,000점 유지, 파울공 1개, 16합 |
| 파울공에 막힌 경로 | 예상 0점, 서쪽 방향에 파울공 | 파울 제거 1회, AI 2,000→400점, 턴 중 제거한 파울공이 종료 후 1개로 복원, 복원 대기 0개, 16합 |
| 위험 샷 조건 | 손님 104,000점·AI 4,000점, 안전 후보, 경로 밖 파울공 | 위험 샷 1회·파울 제거 0회, AI 4,000→800점, 종료 후 위험 샷 예약 해제·파울공 1개, 16합 |

세 경우 모두 턴 종료 후 `story_item_used_this_turn=0`으로 초기화됐다. 첫 경우의 고정 후보는 **예상** 1,600점이지만 실제 샷은 득점하지 않았다. 마지막 경우도 실제 샷의 득점은 없었다. 아이템 선택과 턴 정산을 판별하는 데 필요한 상태는 로그에 남아 있다.

## 검증 자료와 제한

- `compile.log`: 검증 빌드 컴파일 로그.
- `runner_stdout.txt`: `ITEM_PLAY_START`와 `ITEM_PLAY_END` 3쌍 및 Runner 종료 코드 0의 근거.
- `bartender_item_playcheck.win`: 고정 배치 재현용 검증 빌드. 정식 게임 빌드가 아니다.
- 제한된 실행 환경의 Runner는 Windows DLL 재할당 오류로 시작하지 못했다. 일반 실행 권한에서 같은 빌드를 실행해 세 턴을 완료했다.
- 세 상황에서 우선순위와 턴 종료 상태에 문제를 발견하지 않아 게임 로직은 수정하지 않았다. 게임 화면이나 규칙을 바꾸지 않았으므로 이 작업의 새 비포·애프터 화면 촬영은 없다.
