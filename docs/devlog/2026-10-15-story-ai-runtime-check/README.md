# 개발 일지: 스토리 AI 검증 룸 실행과 샷 선택 개선

날짜: 2026-10-15  
화면: `rm_story_ai_verify`, 1280×720, 60 FPS  
목적: 플레이어 턴 뒤 AI가 2~5쿠션으로 실제 득점하는지 확인

## 작업 전 상태

`rm_story_ai_verify`는 이미 프로젝트에 등록되어 있었지만 메뉴에는 진입 버튼이 없었다. 원본 프로젝트를 바꾸지 않고 룸 순서만 바꾼 임시 `verify_project.yyp`로 실행했다. 기존 기록에는 Runner가 없어 촬영 불가라고 적혀 있었으나, 이번에 GameMaker 런타임의 `windows/x64/Runner.exe`를 찾아 직접 실행했다.

첫 실행에서 `global.score_gain_fx` 미초기화로 Runner가 종료 코드 1과 함께 멈췄다. 콘솔 오류는 `physics_scan_ball_collisions`에서 `score_gain_fx`를 읽기 전에 설정하지 않았다는 내용이었다. 초기 화면은 [작업 전 검증 룸](before/verify-room.png), [5초 영상](before/verify-room-idle.mp4)에 남겼다.

초기화 오류를 고친 뒤 같은 고정 배치에서 AI가 **4쿠션을 예측하고 실제로 4쿠션을 쳤지만 목표 공을 못 맞혀 MISS**가 났다. 후보 선택 개선 직전의 코드를 별도 복제본에서 재구성해 같은 입력으로 다시 촬영했다. [수정 전 결과](before/ranking-final.png)와 [수정 전 30초 영상](before/ranking-player-ai-turn.mp4)에는 `AI PRED 4 / ACTUAL 4`, `AI RESULT MISS`, AI 기회 `3→2`가 보인다. 이 복제본은 최초 AI 구현 이전 버전이 아니라 **샷 선택 변경 직전 버전**이다.

`before/failed-capture-occluded.mp4`는 다른 앱 창이 겹친 최초 녹화 시도라 비교 증거로 사용하지 않는다.

## 변경 사항

1. 검증 룸의 규칙 초기화에 `score_gain_fx` 기본 상태를 추가해 목표 공 접촉 때 발생하던 런타임 오류를 제거했다.
2. AI 시뮬레이션에서 목표 공을 맞힌 **이후**의 파울 접촉도 계속 기록하도록 했다. 실제 게임 규칙은 그 경우 점수를 무효화한다.
3. 후보마다 조준 각도 `−1°, −0.5°, 0°, +0.5°, +1°`를 시뮬레이션한다. 5개 중 3개 이상이 파울 없이 2~5쿠션 득점인 후보만 고려하고, 다섯 결과의 평균 점수에서 파울 위험을 뺀 값으로 선택한다.
4. 검증 화면에 AI의 예측 쿠션 수, 실제 쿠션 수와 실제 득점·파울·실패 결과를 표시했다. `tools/capture_story_ai.ps1`은 같은 초기 배치에서 플레이어 공 `(380,350)`을 `(180,350)` 방향으로 끌어 샷을 실행하고 게임 창을 촬영한다.

## 작업 후 확인

같은 검증 룸과 스크립트 입력으로 30초 촬영한 [결과 화면](after/final.png)과 [영상](after/player-ai-turn.mp4)에서 AI가 `AI PRED 3 / ACTUAL 3`, `AI RESULT +800`을 기록했다. AI 점수는 `0→800`, AI 기회는 3으로 유지됐고 플레이어 기회는 2로 따로 표시됐다. [초기 화면](after/initial.png)은 촬영 시작 시 고정 배치를 보여준다.

`tools/test_story_versus.py`는 `score_gain_fx` 초기화와 목표 공 이후 파울 판정을 포함한 검사를 통과했다. GameMaker Igor VM 컴파일도 통과했고, 실제 Runner의 이번 30초 촬영에서 오류 출력은 없었다.

## 범위와 남은 확인

이 영상은 **한 가지 고정 배치와 입력에서 3쿠션 득점이 성공했다는 증거**다. 모든 배치에서 최적 점수를 찾는다는 수학적 증명은 아니며, 실제 물리와 AI 시뮬레이션 사이의 충돌 순서 차이도 완전히 제거되지는 않았다. 더 많은 배치에서 실제 쿠션 수, 파울, 득점을 반복 측정해야 한다. 검증 룸은 메뉴에 연결하지 않았으며 스토리 모드 통합도 이번 작업 범위 밖이다.

최초 AI 구현 **이전**의 스크린샷과 영상은 존재하지 않는다. 이 일지는 실행 검증 과정의 오류 수정과 샷 선택 개선을 비교한다.
